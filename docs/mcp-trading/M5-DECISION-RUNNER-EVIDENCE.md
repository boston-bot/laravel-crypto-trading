## Delivered behavior

- A separate `paper-decision-v1` proposal contract reuses M3's PHP OpenAI Responses transport and shared decimal budget ledger. M3 research keeps its existing contract and cache. No new SDK, service or strategy engine was introduced.
- `MCP_PAPER_DECISIONS_ENABLED=false` is an independent default gate. Existing research enablement, provider/model/credential, reviewed prices and fixed-cost readiness must also pass. An applied complete paper policy and a verified regular market session are required. Saving or applying rules does not enable this gate.
- `php artisan mcp:paper-decisions --once [--sync]` handles only the current session-open-anchored window, using the applied `decision_minutes`. When enabled, the existing Laravel scheduler checks once per minute and uses the existing research queue/worker. There is no historical catch-up. A policy frequency change affects future windows, without another scheduler or replaying completed work.
- Each proposal captures policy/guidance and revision, ledger/auth generation, virtual cash/reservations, bounded evidence and expiry. The encrypted request record includes instructions, schema, model, output-token cap, source mapping and input; it is saved before the call attempt. The captured technical quote-age guard is currently 60 seconds and is rechecked when output returns. This is a proposal validation default, not owner approval of a live trading rule.
- Strict semantic validation rejects unsupported/duplicate symbols, invented citations, future evidence, expired output, unknown eligibility/positions, stale or missing quotes, float sizing, extra settings and allocation/position violations. WAIT/HOLD carry no sizing; HOLD requires a known positive paper holding. Synthetic eligible BUY output can become `proposed`, always with `executable=false` and further execution checks required. No order, fill, cash or position mutation exists in this runner.
- Policy, ledger, account authorization, enablement, window and lease are checked again after the model returns. Paid results invalidated in flight remain recorded as superseded/expired. Model text cannot change settings, grant eligibility or acquire tools.
- The account-scoped Control Center shows the applied interval, readiness, next eligible current-session review, recorded call attempts/responses, observed gap between the last two attempts, and paginated request/result/validation/cost evidence. Attempt time means intent recorded before invoking the adapter; it does not prove provider acceptance. Current prompt preview is separate from historical request evidence. All displayed text is escaped.

## Costs, duplicate work and recovery

One logical run has at most one paid attempt, with no automatic format repair or model retry. Window uniqueness and a unique active-portfolio claim prevent duplicate workers from independently processing the same run. A lost queued dispatch can be redispatched; an already claimed/completed run cannot become a second paid attempt.

Atomic reservations share M3's monthly ledger. Admission uses the lower of the global and applied paper envelopes, including fixed costs, spent and in-flight reservations; a narrower paper cap does not rewrite the shared or historical global envelope. Reviewed input/output rates are captured before the attempt and used for settlement even if configuration changes in flight. Returned usage determines the estimated cost at those rates; it is not a provider invoice. Unknown usage, timeout and abandoned workers conservatively consume the full reservation. Explicit provider rejection is unbilled. Budget deferrals create local incidents.

No database transaction is held across the model call. Expired queued work is recorded without a call; expired worker leases are abandoned and settled once. A late result is retained as evidence without promotion, replay or double settlement. The database claim controls local logical work; it cannot prove that an external provider stopped processing after a network timeout.
